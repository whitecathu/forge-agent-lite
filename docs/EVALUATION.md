# 评测与证据

固定集共 12 个纯 Python 任务：加法修复、区间裁剪、保序去重、均值边界、列表分组、slug 规范化、不可变字典合并、回文、嵌套展开、半开区间、测试补充和除零修复。每个任务都包含待修复源码、可运行的基本测试与独立验收测试。

默认 `uv run python -m evals.run` 只做清单完整性检查，**不是 Agent 完成率**。评测脚本不会在缺 fixture 时用空 README 替代真实题目。

真实评测需显式 `--live`、模型配置和预先构建的 Docker runner。先用 `--limit 1 --max-calls 10`，每题包含规划的调用数最多为指定值；费用上限还应在模型服务商侧设置。脚本不尝试估算未知价格。

验收条件：运行时 pytest 验证通过，且独立 `/acceptance` 测试也通过。验收目录不在 Agent 文件工具的工作区内，并在容器执行时只读挂载。它不能保证完全防止恶意作弊；当前评测面向正常编码任务，未来可用进程外黑盒服务进一步隔离验收逻辑。

报告保存 live 标记、代码提交、数据集哈希、模型名、每题 run_id、状态、用量、修复轮数、耗时与外部验收输出。平均任务完成率只来自实际执行。测试补充任务的外部检查是基础存在性检查，测试质量还需人工审核，不将其等同于覆盖率改善。

离线单元测试中的 Scripted 模型只验证控制流、文件边界、失败修复、预算与恢复。Docker 集成测试运行真实容器，但仍不能证明真实 LLM 能解决任务。

目前没有填写真实模型完成率、首轮成功率或成本数字。可复现工程证据与模型能力证据分开交付。
