# 面试讲解

## 60 秒介绍

我把编码 Agent 收敛为一个可解释的工程循环：先生成计划，确认后通过六类工具读取和修改隔离 worktree，最后在禁网 Docker 容器中运行 pytest。模型停止调用工具不代表任务成功，只有验证通过才能进入成功状态。SQLite 记录检查点和工具调用结果，支持工具边界暂停与恢复。项目有 CLI 和 Web 两个入口，以及 12 个独立验收任务。真实模型效果与离线控制流测试严格区分。

## 常见追问

**为什么不做多 Agent？** 当前任务是短程 Python 修复，单模型工具循环更易追踪、评测和限制预算。没有证据说明多个角色一定更有效，避免用角色命名代替实际协作架构。

**为什么选 LangGraph？** 显式节点和检查点便于表达计划、工具、验证、修复与暂停。编排框架不会自动提供权限或沙箱，工具边界与 Docker runner 需要自己实现。

**如何防止恢复重复写入？** 每次工具调用先记 started，完成后记 done；重放 done 返回原结果。写文件还需要内容哈希一致。started 的不确定状态不能自动重试，也不能宣称实现全局 exactly-once。

**Docker 就一定安全吗？** 不是。当前固定参数限制测试进程，宿主 Git 操作仍要求可信仓库。没有执行任意主机 shell 的工具，但这不是完整恶意代码托管服务。

**如何避免假成功？** 无测试、测试失败、Docker 不可用、超时都不会通过；真实评测还运行独立验收。即使全通过，也只说明测试断言满足，不等于证明程序正确。

**怎么证明项目价值？** 展示可运行任务、Diff、失败案例、测试与评测实现。调用数、耗时与完成率来自真实报告；不要填写模板式“提升 30%”或虚构用户数。
